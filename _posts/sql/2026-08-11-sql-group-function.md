GROUP BY는 데이터를 그룹으로 나눠 집계하는 기본 문법이지만, 실무에서는 한 번의 쿼리로 여러 수준의 소계를 동시에 구해야 할 때가 많다. 그럴 때 쓰는 게 바로 ROLLUP, CUBE, GROUPING SETS, GROUPING 함수들이다. SQLD 시험에도 자주 나오니 이번 기회에 정리해두자.

---

## ROLLUP — 계층적 소계

#### 개념
GROUP BY ROLLUP(A, B)를 쓰면 A와 B로 그룹화한 결과 외에도, A만으로 그룹화한 소계, 그리고 전체 합계까지 한 번에 나온다. **순서가 매우 중요하다.** 앞에 있는 컬럼이 상위 개념이다.

#### 결과 구조
예를 들어 ROLLUP(부서, 직급)을 쓰면 다음 4가지 그룹이 나온다:
- (부서, 직급) 별 세부 집계
- (부서) 별 소계 (모든 직급 합친 것)
- () 전체 총합 (모든 부서 합친 것)

#### SQL 예시

```sql
SELECT 부서, 직급, COUNT(*) AS 인원수, SUM(급여) AS 급여합
FROM 직원
GROUP BY ROLLUP(부서, 직급)
ORDER BY 부서, 직급;
```

**결과:**
| 부서 | 직급 | 인원수 | 급여합 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| 영업 | 과장 | 5 | 250,000 | |
| 영업 | 대리 | 3 | 180,000 | |
| 영업 | NULL | 8 | 430,000 | ← 영업 부서 소계 |
| 개발 | 과장 | 4 | 200,000 | |
| 개발 | 대리 | 6 | 320,000 | |
| 개발 | NULL | 10 | 520,000 | ← 개발 부서 소계 |
| NULL | NULL | 18 | 950,000 | ← 전체 총합 |

#### 핵심 특징
- ROLLUP(A, B, C)의 그룹 개수 = **N + 1개** → 4개 그룹 생김
  - (A, B, C), (A, B), (A), ()
- 계층 구조가 명확하고, 위에서 아래로 차수를 줄여나감
- ROLLUP(부서, 직급)과 ROLLUP(직급, 부서)의 결과는 다르다
- B 기준 소계(직급별 전체 합)는 나오지 않음

---

## CUBE — 모든 조합의 소계

#### 개념
CUBE는 지정된 모든 컬럼의 조합 가능한 경우의 수를 전부 구한다.
#### 결과 구조
CUBE(A, B)를 쓰면 다음 4가지 그룹이 나온다:
- (A, B) 별 세부 집계
- (A) 별 소계
- (B) 별 소계 ← ROLLUP에는 없는 것!
- () 전체 총합

#### SQL 예시

```sql
SELECT 부서, 직급, COUNT(*) AS 인원수, SUM(급여) AS 급여합
FROM 직원
GROUP BY CUBE(부서, 직급)
ORDER BY 부서, 직급;
```

**결과 (일부):**
| 부서 | 직급 | 인원수 | 급여합 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| 영업 | 과장 | 5 | 250,000 | |
| 영업 | 대리 | 3 | 180,000 | |
| 영업 | NULL | 8 | 430,000 | ← 영업 부서 소계 |
| 개발 | 과장 | 4 | 200,000 | |
| 개발 | 대리 | 6 | 320,000 | |
| 개발 | NULL | 10 | 520,000 | ← 개발 부서 소계 |
| NULL | 과장 | 9 | 450,000 | ← 과장 직급 소계 (ROLLUP엔 없음!) |
| NULL | 대리 | 9 | 500,000 | ← 대리 직급 소계 (ROLLUP엔 없음!) |
| NULL | NULL | 18 | 950,000 | ← 전체 총합 |

#### 핵심 특징
- CUBE(A, B, C)의 그룹 개수 = **2^N개** → 2³ = 8개 그룹 생김
- 각 컬럼마다 독립적으로 소계가 나옴
- 순서는 상관없다 (ROLLUP과 달리!)
- 다차원 분석이나 BI 대시보드에서 유용함

## GROUPING SETS — 지정한 그룹만 집계

#### 개념
GROUPING SETS를 쓰면 "이 그룹과 저 그룹만 구하겠다"고 명시할 수 있다. 모든 조합을 구하는 게 아니라, 필요한 것만 골라 계산한다.

#### 결과 구조
GROUPING SETS((A), (B))를 쓰면 다음 2가지 그룹만 나온다:
- (A) 별 소계
- (B) 별 소계
- 전체 총합 () 은 자동으로 추가됨

#### SQL 예시

```sql
SELECT 부서, 직급, COUNT(*) AS 인원수, SUM(급여) AS 급여합
FROM 직원
GROUP BY GROUPING SETS((부서), (직급))
ORDER BY 부서, 직급;
```

**결과:**
| 부서 | 직급 | 인원수 | 급여합 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| 영업 | NULL | 8 | 430,000 | ← 영업 부서 합계 |
| 개발 | NULL | 10 | 520,000 | ← 개발 부서 합계 |
| NULL | 과장 | 9 | 450,000 | ← 과장 직급 합계 |
| NULL | 대리 | 9 | 500,000 | ← 대리 직급 합계 |

#### 핵심 특징
- 지정한 그룹만 구함 (CUBE처럼 모든 조합을 구하지 않음)
- GROUPING SETS((A), (B), (A,B))로 원하는 조합만 명시 가능
- GROUPING SETS()를 넣으면 전체 합도 함께 나옴
- 필요한 것만 계산하므로 가장 효율적일 수도 있음

## GROUPING() — 소계 행 판별 함수

#### 개념
ROLLUP이나 CUBE를 쓰면 소계와 총합 계산 때문에 결과에 NULL 값이 생긴다. 이 NULL이 "원래 데이터가 NULL인 건지, 아니면 소계 때문에 생긴 NULL인지" 구분하는 함수다.

#### 출력값
- **0** : 해당 컬럼이 정식으로 그룹화되어 집계에 사용된 것 (일반 데이터 행)
- **1** : 해당 컬럼이 소계/합계 계산으로 인해 NULL인 것 (소계 행)

#### SQL 예시

```sql
SELECT 
    CASE WHEN GROUPING(부서) = 1 THEN '전체' ELSE 부서 END AS 부서,
    CASE WHEN GROUPING(직급) = 1 THEN '소계' ELSE 직급 END AS 직급,
    COUNT(*) AS 인원수,
    SUM(급여) AS 급여합
FROM 직원
GROUP BY ROLLUP(부서, 직급)
ORDER BY 부서, 직급;
```

**결과:**
| 부서 | 직급 | 인원수 | 급여합 | 비고 |
| :--- | :--- | :--- | :--- | :--- |
| 영업 | 과장 | 5 | 250,000 | |
| 영업 | 대리 | 3 | 180,000 | |
| 영업 | 소계 | 8 | 430,000 | ← 영업 부서 소계 |
| 개발 | 과장 | 4 | 200,000 | |
| 개발 | 대리 | 6 | 320,000 | |
| 개발 | 소계 | 10 | 520,000 | ← 개발 부서 소계 |
| 전체 | 소계 | 18 | 950,000 | ← 전체 총합계 |

#### 핵심 특징
- GROUPING(컬럼) 형태로 사용
- CASE 문과 함께 쓸 때 진가를 발휘함
- 보고서나 BI에서 소계/합계 행을 명확히 표시할 때 필수적
- 원래 NULL과 소계로 인한 NULL을 구분 가능

---

## 비교표로 한눈에 정리

| 함수 | 결과 그룹 | 계층 구조 | 순서 중요 | 사용 시기 |
|------|---------|---------|---------|---------|
| **ROLLUP(A,B)** | (A,B), (A), () | 있음 | 매우 중요 | 상위/하위 계층 분석 |
| **CUBE(A,B)** | (A,B), (A), (B), () | 없음 | 상관없음 | 다차원 분석 |
| **GROUPING SETS** | 지정한 것만 | 없음 | 상관없음 | 선택적 집계 |
| **GROUPING()** | 0 또는 1 | - | - | NULL 판별 |

---

## SQLD 시험 암기 팁

#### 그룹 개수 공식
- ROLLUP(A, B, C) = 4개 → **N + 1**
- CUBE(A, B, C) = 8개 → **2^N**
- GROUPING SETS는 명시한 개수 = **자유**

#### 단골 시험 패턴
```sql
SELECT 
    CASE WHEN GROUPING(컬럼) = 1 THEN '총합계' ELSE 컬럼 END,
    ...
FROM 테이블
GROUP BY ROLLUP(컬럼1, 컬럼2);
```
이 형태가 거의 매번 출제된다. GROUPING()으로 소계 행을 판별해서 이름을 붙이는 패턴은 필수 암기.

#### 헷갈리기 쉬운 부분
- ROLLUP(부서, 직급)은 **"직급 기준 소계는 나오지 않는다."**
- CUBE는 모든 조합이 다 나온다 (4개 그룹, 모든 각도 커버)
- GROUPING()은 함수지 연산자가 아니다
- NULL과 소계 NULL은 다르다!

---

## 정리

각 함수의 쓰임새를 명확히 구분하자:

- **ROLLUP** — 계층 구조가 있을 때 (부서 > 직급 > 개인)
- **CUBE** — 모든 각도에서 분석하고 싶을 때 (다차원 분석)
- **GROUPING SETS** — 딱 필요한 그룹만 구하고 싶을 때 (효율성)
- **GROUPING()** — 소계/합계 행을 구분해서 표시할 때 (보고서 포맷)

넉 개를 다 이해하면 집계 쿼리는 자유자재로 작성할 수 있다. 실무에서도 복잡한 보고서를 한 번의 쿼리로 정리할 수 있으니, 꼭 알아두자

# 시험대비 그룹 함수 핵심 정리


## 1분 요약

| 함수 | 결과 | 개수 | 핵심 |
|------|------|------|------|
| **ROLLUP(A,B)** | (A,B), (A), () | **N+1** | 계층적, 순서 중요 |
| **CUBE(A,B)** | (A,B), (A), (B), () | **2^N** | 모든 조합 |
| **GROUPING SETS** | 지정한 것만 | 자유 | 효율적 |
| **GROUPING()** | 0 or 1 | - | NULL 판별 |

---

## 핵심 공식 암기

### ROLLUP 그룹 개수
```
ROLLUP(A) = 2개
ROLLUP(A, B) = 3개 ✓
ROLLUP(A, B, C) = 4개 ✓
ROLLUP(A, B, C, D) = 5개 ✓

공식: N + 1
```

### CUBE 그룹 개수
```
CUBE(A) = 2개 (2^1 = 2)
CUBE(A, B) = 4개 (2^2 = 4) ✓
CUBE(A, B, C) = 8개 (2^3 = 8) ✓
CUBE(A, B, C, D) = 16개 (2^4 = 16)

공식: 2^N
```

---

## 각 함수 특징 한 줄 정리

### ROLLUP
- **계층적 소계**를 원할 때
- 순서: 부서 > 직급 > 개인 (점점 세분화)
- 결과 구조: (A,B,C), (A,B), (A), ()
- 특징: **B만의 소계는 없다** ← 중요!

### CUBE
- **모든 각도의 소계**를 원할 때
- 순서 상관없음
- 결과 구조: (A,B), (A), (B), ()
- 특징: **각 컬럼 단독 소계 포함** ← ROLLUP과의 차이!

### GROUPING SETS
- **원하는 그룹만** 구할 때
- 계층 구조 없음
- `GROUPING SETS((A), (B))` → (A) 소계, (B) 소계만 나옴
- 특징: 불필요한 계산 생략 (효율적)

### GROUPING()
- **소계/합계 행 판별**할 때
- 출력: 0(일반 행) or 1(소계 행)
- CASE WHEN과 자주 조합
- 특징: **원래 데이터 NULL과 구분**할 수 있음

---

## 헷갈리기 쉬운 포인트

### ❌ 자주 틀리는 것
1. ROLLUP 그룹 개수를 CUBE처럼 2^N으로 생각하기
   - ✓ ROLLUP(A,B) = 3개 (N+1)
   - ✗ ROLLUP(A,B) = 4개 (2^2)

2. ROLLUP(부서, 직급)에서 직급 기준 소계가 나올 것으로 기대하기
   - ✗ 직급 소계는 없다!
   - CUBE를 써야 나온다

3. GROUPING()을 단순 함수로 생각하기
   - ✓ ROLLUP/CUBE/GROUPING SETS와 함께 쓰는 판별 함수
   - ✗ 단독으로 쓰지 않음

4. NULL을 그냥 NULL로 처리하기
   - 원본 데이터의 NULL vs 소계의 NULL은 다름
   - GROUPING()으로 구분해야 함

## 시험 출제 패턴

### 패턴 1: 그룹 개수 세기 ![star]![star]![star]

**문제 예시:**
```sql
SELECT 부서, 직급, SUM(급여)
FROM 직원
GROUP BY ROLLUP(부서, 직급);
```
"위 쿼리의 SUM(급여) 행이 몇 개 출력되는가?"

**풀이:**
- ROLLUP(부서, 직급) = 3개 그룹
- 부서 2개(영업, 개발) × 직급 2개(과장, 대리) = 4개 행
- 부서별 소계 2개
- 전체 합 1개
- **답: 7개 행**

### 패턴 2: CASE + GROUPING ![star]![star]![star]

**문제 예시:**
```sql
SELECT 
    CASE WHEN GROUPING(부서) = 1 THEN '총합' ELSE 부서 END,
    직급,
    COUNT(*)
FROM 직원
GROUP BY ROLLUP(부서, 직급);
```
"GROUPING(부서) = 1인 행은 몇 개인가?"

**풀이:**
- GROUPING(부서) = 1 → 부서가 소계/합계로 NULL인 행
- 부서별 소계 2개 + 전체 합 1개
- **답: 3개 행**

### 패턴 3: ROLLUP vs CUBE 비교 ![star]![star]

**문제 예시:**
"GROUP BY ROLLUP(A, B)와 GROUP BY CUBE(A, B)의 결과 차이는?"

**답:**
- ROLLUP: (A,B), (A), () = 3개
- CUBE: (A,B), (A), (B), () = 4개
- **차이: (B) 소계 여부**

### 패턴 4: GROUPING SETS 활용 ![star]

**문제 예시:**
```sql
GROUP BY GROUPING SETS((부서, 직급), (부서))
```
"생성되는 그룹은 몇 개인가?"

**풀이:**
- (부서, 직급) 조합
- (부서) 소계
- 자동 추가: ()
- **그룹 개수 = 지정한 것 + ()**

## 기출 단골 문제

### 1번 유형: "소계 행만 추출"
```sql
SELECT *
FROM (
    SELECT 부서, 직급, SUM(급여),
           GROUPING(부서) gp1,
           GROUPING(직급) gp2
    FROM 직원
    GROUP BY ROLLUP(부서, 직급)
) t
WHERE gp1 = 1 OR gp2 = 1;
```
→ 부서 소계와 전체 합만 나온다

### 2번 유형: "계층 표시"
```sql
SELECT 
    CASE WHEN GROUPING(부서) = 1 THEN '전사'
         WHEN GROUPING(직급) = 1 THEN '부서 합계'
         ELSE 직급
    END AS 직급_분류,
    SUM(급여)
FROM 직원
GROUP BY ROLLUP(부서, 직급);
```
→ 보고서 형식으로 출력

### 3번 유형: "비교 분석"
```sql
-- ROLLUP 결과
SELECT 부서, COUNT(*) FROM 직원 GROUP BY ROLLUP(부서);
-- vs
-- CUBE 결과
SELECT 부서, COUNT(*) FROM 직원 GROUP BY CUBE(부서);
```
→ CUBE가 더 많은 조합을 포함

## 암기 팁

### 숫자로 기억하기
- **ROLLUP → 3** (N+1, 부서2개×직급2개+소계1개)
- **CUBE → 4** (2^2)
- **GROUPING → 0 or 1** (판별값)

### 단어 연상
- **ROLLUP** = 롤업 = 계층적으로 굴린다 = 상위로 올라감
- **CUBE** = 정육면체 = 모든 면이 드러남 = 모든 조합
- **GROUPING SETS** = 집합 = 원하는 것만 선택
- **GROUPING()** = 그룹인가 판별 = 0/1 이진값

### 문제 풀이 체크리스트
1. ROLLUP인가, CUBE인가? → 그룹 개수 확인
2. GROUPING()이 있는가? → 소계 행 관련
3. NULL이 나왔는가? → GROUPING()으로 판별 필요
4. 표시할 그룹이 제한적인가? → GROUPING SETS 활용

## 최종 정리표

```
함수 사용 결정 트리

복수 수준의 소계가 필요한가?
├─ YES: ROLLUP 또는 CUBE를 써야 함
│  ├─ 계층 구조가 있는가? (부서 > 직급)
│  │  └─ YES: ROLLUP(부서, 직급)
│  └─ 모든 각도를 봐야 하는가?
│     └─ YES: CUBE(부서, 직급)
│
└─ 특정 그룹만 필요한가?
   └─ YES: GROUPING SETS((부서), (직급))

소계/합계 행을 구분해서 표시해야 하는가?
└─ YES: GROUPING(컬럼) = 1 사용
```

## 실전 풀이 예

**문제:** 다음 쿼리 결과에서 GROUPING(부서) = 1이고 GROUPING(직급) = 0인 행이 몇 개인가?
```sql
SELECT 부서, 직급, COUNT(*),
       GROUPING(부서), GROUPING(직급)
FROM 직원
GROUP BY CUBE(부서, 직급);
```

**풀이:**
1. CUBE(부서, 직급)는 (부서, 직급), (부서), (직급), () 4개 그룹
2. GROUPING(부서) = 1: 부서가 NULL (소계 행)
3. GROUPING(직급) = 0: 직급이 값을 가짐 (일반 행)
4. 두 조건을 동시에 만족: **(직급) 소계 행**
5. 직급이 2개면 2개 행

**답: 2개**
