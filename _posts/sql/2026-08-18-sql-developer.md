### 1-1. 증상: 쿼리 글씨가 뭉개진다

고해상도 모니터에서 SQL Developer를 쓰면 글자가 흐릿하게 번져 보임.
윈도우 디스플레이 배율(125%/150%/200%)이 적용된 환경에서 프로그램이 고DPI를 스스로 인식하지 못할 때 발생.
윈도우가 저해상도로 그려진 화면을 비트맵으로 그냥 확대해버리는 것이 원인.

### 1-2. 1차 시도: 윈도우 고DPI 재정의 (실패)

`sqldeveloper.exe` 우클릭 → 속성 → 호환성 → 고DPI 설정 변경 →
"고DPI 조정 동작을 재정의합니다" 체크 → **시스템(고급)** 선택.

<img width="841" height="835" alt="20" src="https://github.com/user-attachments/assets/3f196d76-140c-4577-b228-5ccc55f69631" />
<br>

세 가지 옵션의 차이:

| 옵션 | 동작 | SQL Developer에서의 효과 |
|---|---|---|
| 시스템(System) | OS가 96DPI 기준으로 그린 뒤 확대 | 거의 없음 |
| 시스템(고급) | GDI 텍스트 렌더링 개선 후 확대 | **자바 앱이라 효과 미미** |
| 응용 프로그램 | 앱 자체 DPI 인식에 위임 | DPI-unaware 앱이면 무효 |

**핵심 포인트**: "시스템(고급)"은 GDI 기반 렌더링을 개선하는 옵션인데,
SQL Developer는 자바 Swing 기반이라 GDI로 글씨를 그리지 않는다.
그래서 다른 구형 프로그램에는 잘 먹히는 이 옵션이 여기서는 체감이 거의 없다.

### 1-3. 진단 방법 (글에 쓰면 좋을 포인트)

스크린샷을 확대해서 글자 테두리를 관찰하면 원인을 구분할 수 있다.

- **빨강/보라 계열 색 번짐(fringing)이 있음** → 저해상도로 그린 화면을 확대한 것 (진짜 흐림)
- **회색 계열 안티앨리어싱만 있음** → 네이티브로 렌더링된 정상 상태

실제로 DPI 설정 전후를 확대 비교했더니, 설정 후에는 무지개 번짐이 눈에 띄게 줄고
정상적인 회색 안티앨리어싱에 가까워졌다. 다만 "억지로 늘린 느낌"을 벗어난 수준이지
완전히 선명해진 것은 아니었다.

### 1-4. 자바 앱에 실제로 먹히는 해법

`sqldeveloper\ide\bin\ide.conf` 파일 맨 아래에 다음 줄 추가:

```
AddVMOption -Dsun.java2d.uiScale=1.5
```

배율에 맞춰 숫자 조정 (125% → 1.25, 150% → 1.5, 200% → 2).

**주의**: 이 옵션과 윈도우 고DPI 재정의를 동시에 켜면 이중 스케일링이 발생해
오히려 더 이상해질 수 있다. uiScale을 넣었다면 윈도우 재정의는 끄는 편이 낫다.

### 1-5. 별개 이슈: 출력 창이 안 보인다

터미널 창처럼 결과가 뜨는 패널이 안 보이는 문제. 실행 단축키에 따라 뜨는 패널이 다르다.

- **Ctrl+Enter (F9)**: 커서가 있는 단일 문장 실행 → 하단에 **질의 결과** 그리드
- **F5**: 스크립트 전체 실행 → 하단에 **스크립트 출력** 탭

둘 다 안 뜨면 보기(V) 메뉴에서 해당 패널을 다시 켜거나,
창(W) 메뉴에서 패널이 플로팅되어 화면 밖으로 밀려나지 않았는지 확인.
그래도 안 되면 `%APPDATA%\SQL Developer` 안의 `system...` 폴더명을 변경해 설정 초기화.

### 1-6. 한글 깨짐 — 두 가지 원인 구분하기

이 부분이 글에서 제일 유용할 만한 대목. **증상 모양에 따라 원인이 완전히 다르다.**

| 화면에 보이는 모양 | 원인 | 해법 |
|---|---|---|
| 네모박스 □□□ 또는 **박스 안에 물음표** | 폰트에 한글 글리프가 없음 (tofu) | 폰트 교체로 해결 |
| 맥락 없는 이상한 기호 (뷁, ¿ 등) | 인코딩 불일치로 데이터 자체가 깨짐 | 폰트 교체로 해결 안 됨 |

**주의할 함정**: "물음표로 보인다"고 하면 보통 인코딩 문제로 생각하기 쉬운데,
확대해보니 **네모 테두리 안에 물음표가 들어있는 형태**였다.
이건 tofu 글리프, 즉 폰트 문제다. 확대해서 테두리 유무를 확인하는 게 정확한 진단법.

### 1-7. 폰트 교체 — D2Coding

네이버에서 만든 무료 코딩용 폰트. 나눔바른고딕 기반이라 한글이 자연스럽고,
고정폭이라 SQL 정렬이 흐트러지지 않는다.

1. https://github.com/naver/d2codingfont 릴리즈에서 zip 다운로드
2. `.ttf` 파일 우클릭 → **"모든 사용자용으로 설치"** ← 이게 핵심
3. SQL Developer 완전 종료 후 재시작
4. 도구(T) → 환경설정 → 코드 편집기 → 글꼴 → D2Coding 선택

**가장 흔한 실수**: 그냥 "설치"를 누르면 현재 사용자용으로만 설치되어
SQL Developer 폰트 목록에 아예 안 뜬다. 반드시 "모든 사용자용으로 설치".

### 1-8. 결론: 왜 IntelliJ로 갈아탔나

폰트를 고쳐도 UI 자체의 낡은 느낌(자바 Swing 기반, 2010년대 초반 디자인)과
JVM 구동으로 인한 느린 초기 실행은 그대로다. SQL Developer의 구조적 한계.

학생이라면 GitHub Student Developer Pack으로 JetBrains 전 제품을 무료로 받을 수 있고,
IntelliJ Ultimate에는 DataGrip과 사실상 같은 엔진인 Database 툴이 내장되어 있다.

## 2. GitHub Student Pack 신청

### 계정 전략

블로그 등 기존 GitHub 계정이 있다면 **새 계정을 만들지 말고 기존 계정에 학교 이메일만 추가**하는 게 맞다.

- 학생 인증은 계정 단위가 아니라 사람(신원) 단위로 걸린다 → 계정을 늘려도 혜택이 늘지 않음
- 파트너사들이 이메일/결제수단 기준으로 중복 수령을 걸러냄
- 새 계정에 라이선스가 붙으면 매번 안 쓰는 계정으로 로그인해야 해서 오히려 불편

Settings → Emails → Add email address로 학교 메일을 추가하고 인증 링크를 클릭하면,
**계정은 하나 그대로이고 이메일만 두 개 걸린 상태**가 된다. 로그인은 기존과 동일.

### 신청 과정에서 막힌 지점들

**필수 항목(*) 외에는 비워도 됨.** 교직원 이메일 형식 같은 건 선택사항.

**2FA 필수**: 2단계 인증이 켜져 있지 않으면
`Discount request could not be created ... must have two-factor authentication enabled` 에러 발생.
Settings → Security에서 Authenticator 앱으로 2FA 설정 후 재시도.
이때 **Recovery codes는 반드시 저장**해둘 것.

**증빙 서류**: 학생증, 성적표, 재학증명서, 시간표, 강의계획서, 등록금 영수증,
장학금 증서, 포털 스크린샷 중 택 1. 전부 "Dated"(현재 날짜가 찍힌) 서류를 요구한다.
= 현재 재학 중임을 증명해야 한다는 뜻. 졸업자는 해당 없음.
