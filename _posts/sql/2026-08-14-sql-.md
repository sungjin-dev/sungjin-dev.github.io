DECODE 

-> CASE와 동일하게 조건에 따른 다른 값을 반환 

DECODE(기준값, 조건1, 결과1, 조건2, 결과2, ... , DEFAULT값)

주의할점 : DECODE는 CASE보다 문법이 간결하지만 비교 연산(=)만 가능하다. 또한 출력되는 값이나 디폴트값도 모두 동일한 자료형으로 구성되어야만 한다.

기본값 처리  마지막 입력값  ELSE 키워드 사용(미입력 시 NULL)
유연성   낮음            높음

윈도우 함수

WINDOW_FUNCTION([입력값]) OVER ([PARTITIONN BY 컬럼] [ORDER BY 절] [WINDOWING 절])  단, [] 내용은 선택적 사용 가능

반드시 OVER()절과 함께 사용

주의사항 : 윈도우 함수의 ORDER BY는 계산 순서만 지정할 뿐 결과 행에 영향 X 
실제 출력 순서를 보장하려면 쿼리 끝에 별도의 ORDER BY절을 사용해야 한다. 


RANK()  -> 동일 순위 허용, 동일 순위 건너띔

DENSE_RANK()  -> 동일 순위 허용, 동일 순위 이후 순위를 건너뛰지 않음. 

ROW_NUMBER() -> 동일 순위 여부에 상관없이 고유한 값을 순서대로 부여 

Oracle 데이터베이스에서 조회 결과에 대해 임시로 부여된 순차 번호. 순서대로 1부터 매겨지며 테이블에 실제하는 것이 아닌 조회 시점에 일시적으로 생성됨. 대표적인 가상 컬럼(ROWNUM, ROWID, LEVEL)

따라서 테이블 저장 순서가 아닌 조회된 결과 순서에 따라 ROWNUM이 부여됨. 그리고 1부터 시작한다는 점을 명심하자. 

ROWNUM 필터링이 ORDER BY보다 먼저 적용되므로 반드시 인라인 뷰에서 정렬한 이후 ROWNUM 조건 적용 

ROW_NUMBER()에 PARTITION BY를 추가사용해서 지점별로 순위를 부과한 뒤 RN = 1인 결과만 가져온다면 각 지점별로 매출액이 가장 높은 결과만 확인 가능

TOP-N -> SQL Sever에서는 간단하게 구현 가능

SELECT TOP (N) [PERCENT] [WITH TIES] 컬럼 목록
FROM 테이블명
ORDER BY 정렬기준;

WITH TIES를 사용할 때는 반드시 ORDER BY가 있어야 한다. 

Oracle 12c 인라인 뷰 없이 간단하게 TOP-N쿼리 작성 가능

CONNECT BY PRIOR [이전단계 부모값] = [다음에 찾을 자식 컬럼]

ORDER SIBLING BY 같은 계층끼리 정렬(전체 계층 X) 
같은 부모를 가진 형제들끼리만" 방문 순서를 정하는 것

구문                          전개방향               예시

CONNECT_BY_ISLEAF -> 현재 행이 말단인지 여부 확인. 말단이면 '1', 아니면 '0' 반환

CONNECT_BY_ISCYCLE -> Oracle의 계층형 질의에서 순환(Cycle)이 발생했는지 판단할 수 있는 함수. 사이클이 감지되면 1, 그렇지 않으면 0

계층 질의에서는 NOCYCLE을 반드시 사용하는 것이 안전

SYS_CONNECT_BY_PATH(컬럼명, '구분자')

계층 질의에서 현재 행이 루트부터 어떤 경로를 거쳐왔는지 문자열로 표시 

CONNECT_BY_ROOT 현재행의 루트(=최상위) 노드 값을 반환

START WITH: 어떤 행이 "루트가 될 자격이 있는지" 판단하는 조건. 이 조건을 만족하는 행이 1개일 수도, 여러 개일 수도 있음

CONNECT_BY_ROOT: 결과로 나온 각 개별 행이 "정확히 어느 루트에서 뻗어나왔는지"를 그 행에 붙여주는 연산자

sql
-- 루트가 단 하나(대표이사 1명)여도 필요한 경우
SELECT employee_id, last_name, level,
       CONNECT_BY_ROOT last_name AS ceo_name
FROM employees
START WITH manager_id IS NULL
CONNECT BY PRIOR employee_id = manager_id;

여기서 루트(대표이사)는 딱 1명이지만, 말단 직원 행 하나하나에 "대표이사 이름"을 붙이려면 결국 CONNECT_BY_ROOT가 필요. 
PRIOR는 "바로 위 부모"만 알려줄 뿐, 계층을 거슬러 올라가 "맨 꼭대기 값"을 자동으로 가져다주지는 않음. 
이걸 안 쓰면 셀프 조인이나 서브쿼리로 우회해야 함. 

루트가 여러 개일 때: 어느 트리 소속인지 구분하기 위해 사실상 필수
루트가 1개일 때: 필수는 아니지만, 루트의 속성값을 매 행에 편하게 붙이기 위해 사용
