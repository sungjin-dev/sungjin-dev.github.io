# 정보처리기사 실기 코딩 압축 정리: 변수·입출력·파이썬 자료구조·C 포인터

실기 코딩 문제는 결국 무엇을 묻는 걸까? 변수에 값이 어떻게 담기고, 그 값이 함수를 지나면서 어떻게 바뀌는지를 묻는다. 즉, 메모리 그림을 머릿속에 그릴 수 있으면 풀린다.

물론 문법을 외우는 것만으로 맞히는 문제도 있다. 하지만 포인터 문제는 그림 없이는 거의 틀린다. 그래서 이 글은 C·Java·Python 공통 기초부터 파이썬 자료구조, C의 값 전달·주소 전달까지 도식 중심으로 정리했다.

※ 아래 코드 예시는 실제로 실행해서 출력을 확인했다. 시험 범위는 예상치이므로 최신 공지를 함께 확인하는 것이 좋다.

<br>

## 0. 핵기초

공통 기초는 C·Java·Python에서 모두 쓰인다. 언어별로 다른 부분만 따로 표시한다.

<br>

### 1) 변수

변수는 이름과 주소가 있는 빈 상자다. 아무거나 넣을 수 있는 상자가 아니라, 정해진 자료형의 값만 들어간다.

코드를 읽을 때는 항상 그림으로 바꿔서 생각하는 것이 좋다. 선언은 상자를 준비하는 일이고, 초기화는 그 상자에 처음 값을 넣는 일이다. 이걸 조금 유식한 말로 `declaration`과 `initialization`이라고 한다.

![변수 선언과 초기화](01-variable.svg)

```c
int blog;        // 선언: 값이 정해지지 않은 상태
int blog = 1;    // 초기화: 선언과 동시에 첫 값 대입
```

※ C의 지역 변수는 초기화하지 않으면 값이 정해지지 않은 쓰레기 값이 들어 있다. Java의 지역 변수는 초기화 전에 읽으면 컴파일 오류가 난다.
※ Python은 선언이 없다. 값을 대입하는 순간 변수가 만들어지고, 자료형은 변수가 아니라 값이 가진다.

자료형 중 헷갈리기 쉬운 두 가지만 비교한다.

| 자료형 | 설명 | 언어별 차이 | 예시 |
|---|---|---|---|
| String | 문자열 (문자 여러 개) | Java 전용. C는 `char` 배열, Python은 `str` | `"blog"` |
| boolean | 참, 거짓 | Java 전용. C는 `<stdbool.h>`의 `bool`, Python은 `bool` | Java `true`, Python `True` |

Python은 자료형을 따로 붙이지 않는다. 변수 자료형이 나타나는 건 `type(x)`로 확인할 때뿐이다. 즉, 외울 것은 `int`, `float`, `str`, `bool` 정도의 이름이다.

<br>

### 2) 출력함수

출력함수는 언어마다 이름이 다르다. 핵심은 세 가지다. 서식 지정이 되는가, 자동 줄바꿈이 되는가, 어떤 언어에서 쓰는가.

| 출력함수 | 언어 | 설명 | 자체 줄바꿈 |
|---|---|---|---|
| `printf` | C, Java | `"문자열"` 뒤에 서식지정자와 값을 차례로 쓴다 | 없음 |
| `System.out.print` | Java | 왼쪽부터 `+`로 결합. 문자열을 만나면 문자열 결합 | 없음 |
| `System.out.println` | Java | `print`와 같되 끝에 줄바꿈 | 있음 |
| `putchar` | C | 문자 하나 출력 | 없음 |
| `puts` | C | 문자열 출력. `printf("문자열\n")`과 동일 | 있음 |
| `print` | Python | 뭐든 출력. f-string 사용 가능 | 있음 |

※ Java 출력 함수는 항상 `System.out.함수` 형태로 쓴다. 클래스 이름이 앞에 붙는다는 뜻이다.

`printf`는 첫 번째 인자가 문자열이어야 한다. 정수 변수를 그대로 넣으면 오류다. 값을 찍으려면 서식지정자를 거쳐야 한다.

```c
int blog = 1;
printf("hello");        // hello
printf("%d", blog);    // 1
printf(blog);          // 오류: 첫 인자가 문자열이 아니다
```

Java의 `+` 결합은 계산 순서가 결과를 바꾼다.

```java
System.out.println(1 + 2 + "a");   // 3a   (숫자 먼저 계산, 이후 문자열 결합)
System.out.println("a" + 1 + 2);   // a12  (처음부터 문자열 결합)
```

Python은 `print`에 옵션이 있다.

```python
print("a", 1, 2)              # a 1 2
print("a", end="")            # 줄바꿈 없이 출력
print(f"{blog} is my life")  # f-string
```

<br>

### 3) 서식지정자와 제어문자

서식지정자는 `printf` 안에서 값이 들어갈 자리를 정한다. 값이 들어가는 자리표라고 생각하면 쉽다.

| 서식지정자 | 풀어 쓰면 | 설명 | 예시 출력 |
|---|---|---|---|
| `%d` | decimal | 정수 | 255 |
| `%c` | character | 문자 1개 | A |
| `%s` | string | 문자열 (여러 개) | Hello |
| `%f` | floating point | 실수. 기본 소수점 이하 6자리 | 255.000000 |
| `%.1f`, `%.2f` | | 소수점 이하 자릿수 지정 | 255.0, 255.00 |
| `%x` | hexadecimal | 16진수 정수 | ff (255) |
| `%o` | octal | 8진수 정수 | 377 (255) |

※ C에서 `%s`로 출력하려면 `char` 배열의 주소(문자열)가 필요하다. 문자 하나는 `%c`다.
※ 폭 지정도 자주 나온다. `%5d`는 폭 5칸 오른쪽 정렬, `%-5d`는 왼쪽 정렬, `%05d`는 빈 칸을 0으로 채운다.

| 제어문자 | 기능 |
|---|---|
| `\n` | 커서를 다음 줄 처음으로 이동 |
| `\t` | 커서를 일정 간격 띄움 |
| `\0` | 널 문자. C 문자열의 끝을 표시한다 |

### 4) 입력함수 (Python)

파이썬의 `input()` 하나면 입력이 끝난다. C의 `scanf`보다 훨씬 자유롭다. 다만 함정이 하나 있다. 입력은 전부 문자열로 들어온다는 점이다.

![input 함수의 흐름](02-input.svg)

```python
blog = input()
print(blog)                          # 개발

blog = input("뭐든 입력해: ")        # 괄호 안 문구는 입력 전에 화면에 먼저 보여준다 (프롬프트)
print(f"{blog} is my life")          # 개발 is my life
```

숫자가 필요하면 형 변환을 거쳐야 한다.

```python
n = int(input())                       # 정수 하나
a, b = map(int, input().split())       # 공백으로 구분된 정수 두 개
```

비교용으로 다른 언어의 입력도 적어 둔다.

```c
scanf("%d", &n);                       // C: 변수의 주소를 넘긴다
```

```java
Scanner sc = new Scanner(System.in);   // Java
int n = sc.nextInt();
```

## 1. 파이썬 자료구조

<br>

### 1) 리스트

리스트는 자유로운 배열이다. 자바 배열과 달리 자료형도, 크기도 정하지 않는다.

![리스트 인덱스와 2차원 리스트](05-list-index.svg)

```python
blog = [10, 11, 12]
print(blog[0])     # 10   (0이 첫 칸)
print(blog[-1])    # 12   (뒤에서 1번째)
print(blog[-2])    # 11   (뒤에서 2번째)

blog[0] = 20
print(blog)        # [20, 11, 12]  변경 가능
```

리스트는 자바처럼 메서드를 가진 객체다. 자주 나오는 메서드를 먼저 표로 본다.

| 메서드 | 의미 | 주의 |
|---|---|---|
| `append(x)` | 리스트 끝에 `x` 추가 | `x`가 리스트여도 하나의 요소로 들어간다 |
| `extend(iterable)` | 여러 요소를 풀어서 끝에 추가 | 정수를 넣으면 `TypeError` |
| `insert(i, x)` | `i` 위치에 `x` 삽입 | 기존 요소는 뒤로 밀린다 |
| `pop(i)` | `i` 위치 요소를 꺼내고 제거 | `i`를 생략하면 맨 끝. 꺼낸 값을 반환 |
| `remove(x)` | 값이 `x`인 요소 삭제 | 같은 값이 여러 개면 맨 앞 하나만. 없으면 `ValueError` |
| `reverse()` | 순서를 거꾸로 뒤집는다 | 제자리 변경, 반환은 `None` |
| `sort()` | 정렬 (기본은 오름차순) | `reverse=True`면 내림차순 |
| `copy()` | 리스트를 복사 | 얕은 복사 |

실행 전후를 그림으로 비교하면 다음과 같다.

![리스트 메서드 실행 전후](06-list-methods.svg)

```python
# 아래 각 줄은 blog = [10, 11, 12]에서 새로 시작한다고 가정한다
blog.append(13)         # [10, 11, 12, 13]
blog.extend([13, 14])   # [10, 11, 12, 13, 14]
blog.pop()              # 12 반환, 리스트는 [10, 11]
blog.pop(0)             # 10 반환, 리스트는 [11, 12]
blog.reverse()          # [12, 11, 10]

b = [10, 11, 10]
b.remove(10)             # 앞의 10만 삭제 → [11, 10]
```

`append`와 `extend`는 시험에서 단골로 나오는 함정이다. 리스트째 넣느냐, 풀어서 넣느냐의 차이다.

```python
a = [10, 11, 12]
a.append([13, 14])       # [10, 11, 12, [13, 14]]
```

```python
a = [10, 11, 12]
a.extend([13, 14])       # [10, 11, 12, 13, 14]
```

교재 표에 함께 나오는 나머지 함수도 정리한다.

```python
sum([3, 5, 2, 4, 1])         # 15
len([2, 7, 6])               # 3
[2, 1, 3].sort()             # 리스트가 [1, 2, 3]으로 바뀐다 (반환은 None)
a = [2, 1, 3]
a.sort(reverse=True)         # [3, 2, 1]
```

※ `sum()`과 `len()`은 엄밀히 말하면 리스트 메서드가 아니라 내장 함수다. 호출 형태가 `sum(리스트)`인 이유다.

`copy()`는 대입과 다르다. 대입은 상자를 복사하는 게 아니라 같은 상자에 이름표를 하나 더 붙이는 것이다.

```python
a = [1, 2, 3]
b = a            # 같은 리스트를 가리킨다 (별칭)
c = a.copy()     # 새 리스트를 만든다
a[0] = 99
print(b)         # [99, 2, 3]
print(c)         # [1, 2, 3]
```

※ `copy()`는 얕은 복사다. 리스트 안에 리스트가 있으면 안쪽 리스트는 여전히 공유된다.

`enumerate()`는 인덱스와 요소를 묶어서 돌려준다.

```python
data = ['a', 'b', 'c']
for a, b in enumerate(data):
    print(a, b)      # 0 a / 1 b / 2 c
```

2차원 리스트는 리스트 안에 리스트가 들어 있는 구조다. 바깥 인덱스로 행을, 안쪽 인덱스로 열을 고른다.

```python
blog_2d = [[10, 11, 12], [20, 21, 22], [30, 31, 32]]
print(blog_2d[1])       # [20, 21, 22]  두 번째 행 전체
print(blog_2d[2][1])    # 31
```

### 2) 딕셔너리

딕셔너리는 키(key)와 값(value)의 쌍이다. 영어사전의 단어와 뜻처럼, 단어를 찾으면 뜻이 나온다.

![딕셔너리 구조](03-dict.svg)

```python
blog_dic = {"뿌리": "연근", "줄기": "연꽃 줄기", "꽃": "연꽃"}
print(blog_dic["줄기"])     # 연  (인덱싱하듯 key로 값에 접근)
```

키는 변경 불가(immutable) 자료형만 가능하다. 문자열, 정수, 튜플은 되지만 리스트, 집합, 딕셔너리는 안 된다. 값은 아무거나 넣어도 된다.

| 메서드 | 의미 |
|---|---|
| `keys()` | 키만 모아서 반환 |
| `values()` | 값만 모아서 반환 |
| `items()` | 키와 값을 튜플 쌍으로 반환 |
| `get(key, 기본값)` | 키가 없으면 오류 대신 기본값 반환 |

```python
a = {'name': 'kim', 'age': 30}
print(list(a.keys()))        # ['name', 'age']
print(list(a.values()))      # ['kim', 30]
print(a.get('height'))       # None
print(a.get('height', 0))    # 0
print(a['height'])           # KeyError
```

※ `keys()`, `values()`, `items()`는 리스트가 아니라 뷰(view) 객체를 반환한다. 그대로 `print`하면 `dict_values(['kim', 30])` 형태로 나오고, 리스트처럼 보이게 하려면 `list()`로 감싼다. 교재 표에 `['kim', 30]`으로 적힌 건 이해를 돕기 위한 단순화다.
※ Python 3.7부터 딕셔너리는 넣은 순서를 유지한다.

### 3) 집합

집합은 중복을 허용하지 않고, 순서도 없다. 출석부가 아니라 중복 없이 담는 주머니라고 생각하면 된다.

```python
blog_set = {"연근", "연꽃", "연"}
blog_set = set(["연근", "연꽃", "연"])   # 내장 함수 set()으로도 만든다

a = [1, 2, 3, 4, 2, 1]
print(set(a))                 # {1, 2, 3, 4}  중복 제거
```

※ 빈 집합은 `{}`가 아니라 `set()`으로 만든다. `{}`는 빈 딕셔너리다.

| 메서드 | 의미 |
|---|---|
| `add(x)` | 요소 하나 추가 |
| `update(iterable)` | 여러 요소를 풀어서 한 번에 추가 |
| `remove(x)` | 요소 제거. 요소가 없으면 `KeyError` |
| `discard(x)` | 요소 제거. 요소가 없어도 오류 없음 |
| `pop()` | 임의의 요소 하나를 꺼내고 제거 |

![집합 메서드](04-set.svg)

※ `remove`와 `discard`의 차이는 "없을 때"뿐이다. 있으면 둘 다 똑같이 삭제한다.
※ `pop()`은 어떤 요소가 나올지 규격상 보장되지 않는다. CPython에서 작은 정수 집합은 대체로 작은 값부터 나오지만, 그것에 기대면 안 된다.

집합 사이에서는 비트 연산자 모양의 기호가 집합 연산자로 바뀐다. 양옆에 집합이 있으면 집합 연산이라고 읽는 것이 좋다.

| 연산 | 기호 | 예 (`a = {1,2,3}`, `b = {3,4}`) |
|---|---|---|
| 합집합 | `a \| b` | `{1, 2, 3, 4}` |
| 교집합 | `a & b` | `{3}` |
| 차집합 | `a - b` | `{1, 2}` |
| 대칭차집합 | `a ^ b` | `{1, 2, 4}` |

## 2. C언어: 값 전달과 주소 전달

<br>

### 1) 값 전달 vs 주소 전달

함수에 변수를 넘길 때, 값을 복사해서 넘기는 걸까, 원본의 위치를 알려주는 걸까? 값 전달은 서류를 복사해서 건네는 것이고, 주소 전달은 원본이 들어 있는 사물함 번호를 알려주는 것이다. 복사본에 낙서를 해도 원본은 멀쩡하다. 사물함 번호를 알면 원본을 직접 고칠 수 있다.

원본의 주소를 넘겨서 원본을 직접 고치는 방식을 조금 유식한 말로 주소 전달(Call by Reference)이라고 한다.

```c
#include <stdio.h>

void func1(int *p) { *p = 50; }   // 주소로 원본 변경
void func2(int p)  { p = 60; }    // 복사한 값만 변경

int main(void) {
    int i = 10;
    func1(&i);
    printf("%d ", i);
    i = 10;                       // 같은 초기값으로 비교
    func2(i);
    printf("%d", i);
    return 0;
}
```

실행 결과는 `50 10`이다. 그림으로 보면 이유가 분명해진다.

![값 전달과 주소 전달](07-call-by-value.svg)

실행 단계를 따라가 본다.

1. `func1(&i)` 호출 전 `int i = 10`까지 실행한다.
2. `func1(&i)` 실행: `p`에 `i`의 주소(100)가 복사되고, `*p = 50`으로 원본 `i`가 50이 된다.
3. `i`를 10으로 다시 초기화한 뒤 `func2(i)`를 실행한다. 복사본 `p`만 60이 된다.
4. `main`의 `i`는 그대로 10이다. 최종 출력은 `50 10`.

| 구분 | 함수 안에서 바꾸는 대상 |
|---|---|
| 값 전달 (Call by Value) | 값의 복사본을 변경 → 원본은 유지 |
| 주소 전달 (Call by Reference) | 주소가 가리키는 원본을 `*p`로 변경 |

※ C는 주소도 값으로 복사한다. `*p`를 바꾸면 원본이 바뀌지만, `p` 자체를 바꿔도 호출한 쪽의 포인터는 그대로다. 엄밀히 말하면 C에는 진짜 참조 전달이 없고, 시험에서 말하는 주소 전달은 포인터 값을 복사해 넘기는 값 전달이다.
※ Java도 비슷하다. 기본형은 값이 복사되고, 참조형은 참조 값이 복사된다. 그래서 객체의 내용은 바뀌지만, 매개변수에 새 객체를 대입해도 호출한 쪽 변수는 그대로다.

<br>

### 2) 배열 매개변수와 포인터 이동

이번에는 배열을 함수에 넘기는 경우다. 배열 이름은 첫 원소의 주소로 바뀌어 전달된다. 즉, 배열은 사실상 주소 전달처럼 동작한다.

```c
#include <stdio.h>

void change(int a[]) {   // 사실은 int *a 와 같다. 첫 원소의 주소를 받는다
    a[0] = 30;
}

void move(int *p) {
    p++;                  // 복사본 p만 한 칸 이동
    *p = 40;
}

int main(void) {
    int a[] = {10, 20};
    int *p = a;
    change(a);
    move(p);
    printf("%d %d ", a[0], a[1]);
    printf("%d", *p);     // main의 p는 그대로
    return 0;
}
```

실행 결과는 `30 40 30`이다.

![배열 매개변수와 포인터 이동](08-array-pointer.svg)

1. `change(a)`: 배열 원본의 첫 칸이 `a[0] = 30`으로 바뀐다.
2. `move(p)`: `p`의 값(100)이 복사본에 들어가고, `p++`로 복사본이 `a[1]`을 가리킨다. `*p = 40`으로 `a[1]`이 40이 된다.
3. `main`으로 돌아오면 `p`는 여전히 `a[0]`을 가리킨다. 따라서 `*p`는 30이다.

※ 그림의 주소 100, 101은 이해를 위한 예시다. 실제로 `int` 배열의 주소는 4바이트씩 떨어져 있다. `p++`는 주소에 1을 더하는 게 아니라 `sizeof(int)`만큼 이동시킨다.

### 3) 연산자 우선순위

교재의 연산자 우선순위 표를 높은 순서대로 정리했다.

| 대분류 | 중분류 | 연산자 | 결합규칙 |
|---|---|---|---|
| 단항 | 단항 | `!`(논리 not) `~`(비트 not) `++` `--` `sizeof` | 오른쪽 → 왼쪽 |
| 이항 | 산술 | `*` `/` `%` | 왼쪽 → 오른쪽 |
| | 산술 | `+` `-` | 왼쪽 → 오른쪽 |
| | 시프트 | `<<` `>>` | 왼쪽 → 오른쪽 |
| | 관계 | `<` `<=` `>=` `>` | 왼쪽 → 오른쪽 |
| | 관계 | `==` `!=` | 왼쪽 → 오른쪽 |
| | 비트 | `&`(비트 and) | 왼쪽 → 오른쪽 |
| | 비트 | `^`(비트 xor) | 왼쪽 → 오른쪽 |
| | 비트 | `\|`(비트 or) | 왼쪽 → 오른쪽 |
| | 논리 | `&&`(논리 and) | 왼쪽 → 오른쪽 |
| | 논리 | `\|\|`(논리 or) | 왼쪽 → 오른쪽 |
| 삼항 | 조건 | `? :` | 오른쪽 → 왼쪽 |
| 대입 | 대입 | `=` `+=` `-=` `*=` `/=` `%=` `<<=` `>>=` 등 | 오른쪽 → 왼쪽 |
| 순서 | 순서(콤마) | `,` | 왼쪽 → 오른쪽 |

※ 단항 연산자에는 주소 `&`, 역참조 `*`도 포함된다.

표를 외우는 것보다 자주 걸리는 함정 세 가지를 기억하는 편이 효율적이다.

- 비트 연산자는 관계 연산자보다 낮다. `a & b == c`는 `a & (b == c)`로 계산된다. 괄호를 습관처럼 쓰는 것이 좋다.
- `&&`가 `||`보다 우선한다. `a || b && c`는 `a || (b && c)`다.
- 후위 `++`가 `*`보다 먼저 묶인다. `*p++`는 `*(p++)`이므로, 현재 가리키는 값을 읽은 뒤 포인터가 이동한다.

## 마무리

정리하면 이렇다. 변수는 이름 붙은 상자이고, 함수에 넘기는 건 상자의 복사본이거나 상자의 위치다. 리스트·딕셔너리·집합은 상자 안에 무엇을 어떤 규칙으로 담는지가 다를 뿐이다.

문법표를 외우는 것으로 끝내지 말고, 코드를 볼 때마다 메모리 그림을 직접 손으로 그려 보는 것이 좋다. 그림이 그려지면 출력 결과는 따라온다.
