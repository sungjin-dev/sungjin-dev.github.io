프론트엔드 면접에서 타이머 관련 질문 은근히 자주 나온다. "setInterval이랑 setTimeout 차이가 뭐예요?"라는 질문에 표만 외워서 답하면 꼬리 질문에서 막히는 경우가 많다. 
"근데 setInterval 오래 돌리면 왜 오차 생겨요?" 같은 질문. 이 글에서는 기본 개념부터 실무에서 마주치는 오차 문제, 그리고 그걸 해결하는 방법까지 순서대로 정리해본다.


## 1. 타이머 API는 왜 비동기일까

`setInterval(실행할함수, 시간)` 이렇게 쓰는 이 함수, 겉보기엔 단순한데 사실 자바스크립트 엔진 구조를 이해해야 제대로 설명이 된다.

자바스크립트는 싱글 스레드로 동작한다. 근데 `setInterval`이나 `setTimeout`은 브라우저(혹은 Node.js)의 Web API 영역에 위임되는 함수다. 즉 타이머 자체는 자바스크립트 엔진이 아니라 브라우저가 관리하고, 지정한 시간이 지나면 콜백 함수를 태스크 큐(정확히는 매크로태스크 큐)에 넣는다. 그리고 콜 스택이 비어있을 때 이벤트 루프가 그 콜백을 꺼내서 실행한다.

이게 왜 중요하냐면, "1000ms 뒤에 실행된다"는 게 "정확히 1000ms 후 실행 보장"이 아니라 **"1000ms 후 실행 큐에 들어갈 자격이 생긴다"는 뜻**이기 때문이다. 만약 메인 스레드가 다른 무거운 동기 작업을 처리 중이면, 콜백은 큐에서 대기하다가 스레드가 빌 때 실행된다. 그래서 setInterval(fn, 1000)이라고 해도 실제로는 1000ms보다 늦게 실행될 수 있다.

```javascript
setInterval(function() {
  console.log('실행됨');
}, 1000);
```

이 코드는 비동기 방식으로 동작한다. 메인 스레드를 블로킹하지 않고 예약만 걸어두는 거다. 그래서 많은 데이터를 한 번에 동기적으로 처리하려고 하면 코드가 복잡해지는데, 이럴 때 비동기 처리를 적절히 활용하면 구조가 훨씬 깔끔해진다. 예를 들어 메인 페이지 진입 시 필요한 컴포넌트들이 각자 알아서 비동기로 데이터를 불러오게 설계하면, 특정 컴포넌트가 늦게 로딩되더라도 전체 페이지 렌더링이 막히지 않는다. 이게 실무에서 비동기를 쓰는 가장 큰 이유 중 하나다.

## 2. setInterval vs setTimeout, 핵심 차이

| 구분 | setTimeout() | setInterval() |
|---|---|---|
| 동작 방식 | 지정 시간 후 **딱 1번만** 실행 | 지정 간격마다 **무한 반복** 실행 |
| 주 목적 | 지연 작업 (예: 3초 뒤 팝업 닫기) | 주기 작업 (예: 1초마다 시계 갱신) |
| 취소 함수 | `clearTimeout(id)` | `clearInterval(id)` |

### setTimeout — 1회성

```javascript
console.log('시작');

const timeoutId = setTimeout(() => {
  console.log('2초가 지났습니다!');
}, 2000);

// 취소하고 싶으면
// clearTimeout(timeoutId);
```

실행 흐름은 "시작" 찍히고 → 2초 대기 → "2초가 지났습니다!" 찍히고 끝. 한 번 실행되고 나면 자동으로 종료된다.

### setInterval — 반복 실행

```javascript
let count = 0;

const intervalId = setInterval(() => {
  count++;
  console.log(`1초마다 실행 중... (${count}회)`);
}, 1000);

// 취소하고 싶으면
// clearInterval(intervalId);
```

이건 clearInterval을 호출하기 전까지 계속 반복된다. 실무에서 정리(cleanup)를 안 해주면 메모리 누수나 예상치 못한 동작으로 이어지기에, 리액트 같은 프레임워크에서는 컴포넌트 언마운트 시점에 반드시 clearInterval을 호출해줘야 한다. 

참고로 컴포넌트 언마운트(Unmount) 시점이란, 웹 화면을 구성하던 특정 부품(컴포넌트)이 화면에서 완전히 사라지고 제거되는 순간이다. useEffect의 클린업 함수에서 정리하는 패턴이 대표적이다.

면접에서 자주 나오는 포인트 하나 더: setTimeout을 재귀적으로 호출하면 setInterval과 비슷한 반복 효과를 낼 수 있는데, 이 방식이 setInterval보다 안전하다고 평가받는 경우가 많다. 이유는 다음 섹션에서 설명하는 오차 문제와 관련이 있다.


## 3. setInterval, 왜 오차가 쌓일까

이게 면접에서 진짜 자주 나오는 꼬리 질문이다. "setInterval(fn, 1000)을 오래 돌리면 왜 시간이 밀리나요?"

이유는 크게 두 가지다.

**첫째, 콜백 실행 시간이 간격에 포함되지 않는다.** setInterval은 "콜백 실행이 끝난 시점부터 1000ms 후"가 아니라 "이전 실행이 시작된 시점 기준으로 1000ms마다" 큐에 태스크를 넣으려고 시도한다. 
근데 만약 콜백 자체가 실행되는 데 시간이 걸리거나, 메인 스레드가 바빠서 대기가 생기면, 그 지연이 누적된다. 매번 조금씩 밀리는 오차가 쌓여서 나중엔 꽤 큰 차이가 난다.

**둘째, 브라우저의 최소 지연시간 및 백그라운드 탭 스로틀링.** 대부분의 브라우저는 중첩된 타이머 호출에 대해 최소 지연시간(보통 4ms)을 강제한다. 
게다가 탭이 백그라운드로 전환되면 배터리/성능을 위해 타이머 실행 주기를 1초 이상으로 강제로 늦추는 경우도 있다. 
그래서 시계 앱을 만들었는데 사용자가 다른 탭 갔다가 몇 분 뒤 돌아오면, 시계가 실제 시간과 안 맞는 상황이 생긴다.

정리하면, setInterval은 "정확히 N초마다 실행"을 보장하는 API가 아니라 "대략 N초마다 실행을 시도하는" API라고 이해하는 게 맞다.


## 4. 오차 없이 정확한 시간을 다루는 방법

시계, 스톱워치, 카운트다운처럼 정확한 시간이 중요한 기능을 만들 때는 타이머의 실행 횟수나 간격에 의존하면 안 된다. 대신 실제 시각(Timestamp)을 기준점으로 삼아서 매번 경과 시간을 다시 계산하는 방식을 써야 한다.

### 해결책: Absolute Timestamp 기반 계산

```javascript
const startTime = Date.now(); // 시작 시각 기록

setInterval(() => {
  const currentTime = Date.now();
  // 1초씩 더하는 게 아니라, 실제 경과한 시간을 매번 재계산
  const elapsedTime = Math.floor((currentTime - startTime) / 1000);

  console.log('정확하게 경과한 초: ', elapsedTime);
}, 1000);
```

핵심은 "카운터를 1씩 증가시키는" 방식이 아니라, `Date.now()`로 얻은 현재 시각과 시작 시각의 차이를 매번 새로 계산한다는 점이다. 이렇게 하면 타이머 콜백이 0.1초 밀리든, 백그라운드 탭에 갔다가 돌아와서 한참 늦게 실행되든 상관없다. 실제 흘러간 시간을 직접 비교하기 때문에, 콜백이 몇 번 스킵되거나 지연되더라도 화면에 표시되는 값 자체는 항상 정확하다.

이 패턴은 실무에서 카운트다운 타이머, 스톱워치, 라이브 스트리밍 경과 시간 표시 등에 그대로 활용된다. 면접에서 "정확한 타이머는 어떻게 구현하나요"라는 질문 받으면 이 타임스탬프 보정 방식을 설명하면 된다.

### 참고: requestAnimationFrame이라는 대안도 있다

화면 갱신과 관련된 애니메이션이라면 setInterval 대신 `requestAnimationFrame`을 쓰는 게 더 적절한 경우가 많다. 이건 브라우저의 리페인트 주기에 맞춰 실행되기 때문에 애니메이션이 훨씬 부드럽고, 탭이 비활성화되면 자동으로 실행을 멈춰서 배터리 소모도 줄여준다. 다만 이건 "정확히 N초마다"를 보장하는 목적이 아니라 "화면 갱신에 맞춰 최적화된 실행"이 목적이라 시계나 카운트다운처럼 실제 시간 값이 중요한 경우엔 여전히 타임스탬프 기반 보정이 필요하다.

## 5. 면접 대비용 핵심 요약

- setInterval/setTimeout은 브라우저(Web API) 영역에 위임되는 비동기 함수고, 지정 시간은 "그 이후 실행 큐에 등록될 자격이 생기는 시점"이지 "정확히 그 시점에 실행"을 뜻하지 않는다.
- setTimeout은 1회성, setInterval은 반복 실행. 각각 clearTimeout, clearInterval로 취소한다.
- setInterval은 콜백 실행 시간, 브라우저 최소 지연시간, 백그라운드 탭 스로틀링 등의 이유로 오차가 누적될 수 있다.
- 정확한 시간이 중요한 기능은 카운터 증가 방식이 아니라 Date.now() 기반의 절대 시각 비교로 경과 시간을 매번 재계산해야 한다.
- 화면 애니메이션 목적이면 requestAnimationFrame이 더 적합할 수 있지만, 실제 시간 값 자체가 중요하면 타임스탬프 보정은 그대로 필요하다.

이 정도만 정리해두면 개념 질문은 물론이고, "왜 오차가 생기냐", "어떻게 보정하냐" 같은 꼬리 질문에도 흔들리지 않고 답할 수 있다.
